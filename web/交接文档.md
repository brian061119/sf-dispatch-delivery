## 1. 跑起来（5 分钟）

```bash
git clone https://github.com/brian061119/sf-dispatch-delivery.git
cd sf-dispatch-delivery && git checkout YitingQi   # 基建在这个分支
cd web
npm install
npm run dev          # http://localhost:3000
```

- 需要 Node.js ≥ 20（推荐 22）。
- 前端默认把 `/api` 代理到 `http://localhost:8080`。后端地址不同的话：
  `VITE_API_PROXY_TARGET=http://<后端host:port> npm run dev`（Windows PowerShell 用 `$env:VITE_API_PROXY_TARGET="..."; npm run dev`）。
- **后端还没起来时怎么开发？** 用 mock 模式：`VITE_MOCK=1 npm run dev`（PowerShell 用 `$env:VITE_MOCK="1"; npm run dev`）。
  `src/api/mock.js` 提供契约形状的假数据（种子订单/候选方案/会漂移的快递员位置），任意账号密码可登录，
  下单/签收/评价全流程可点，刷新重置。联调时去掉 `VITE_MOCK` 即可，业务代码零改动（开关在 `api/*.js` 每个函数第一行）。

## 3. 必须遵守的 6 条规矩

1. **接口只走 `src/api/`**。组件里禁止直接 `fetch`/`axios`——要新端点，先提契约变更，再在 `api/` 加函数。
2. **契约改动先打招呼**。`api-contract.md` / `src/types/api.js` 是前后端唯一契约，改任何字段/枚举前在群里说一声（前后端同步改）。**前端不发明契约里没有的端点和字段**（取消订单按钮就是这么被"暂扣"的）。
3. **共享状态只走 `src/store/`**。别在组件间用 props 钻三层传数据，也别自己往 localStorage 写东西（token 只有 `lib/auth.js` 能碰）。
4. **公共组件先复用**：`OrderCard` `StatusBadge` `StatusTimeline` `VehicleIcon` `MapView` `AppHeader`（用法见 `设计讲解.md` §4）。
5. **UI 用 antd 组件**，样式微调用 `style` 或主题（`theme.js`），不要引入新的组件库/CSS 框架。
6. **提交信息用英文**，一句话说清干了什么（例：`feat: map click-to-pick in order wizard`）。

## 4. Git 流程

```
YitingQi (基建) ──► main（基建合并后，main 是可运行基线）
main ──► feature/ziyuan-auth
     ──► feature/zihang-order
     ──► feature/y-detail
     ──► feature/yuning-tracking
```

1. 从 `main` 切自己的分支：`git checkout -b feature/<你的名字>-<范围>`
2. 只改自己 owner 的文件；要动公共文件（components/store/api/types）先在群里说。
3. 完成提 PR 到 `main`，找 Yiting 或任意队友 review，过即合。
4. 每天开工前 `git pull origin main` 保持同步。

## 5. 要和后端对齐的待确认清单（下次例会过一遍）

契约里标 TBD 或前端实现时发现的坑，按优先级：

- [ ] **`POST /api/auth/register` 的 body 和响应**（TBD）——前端先按 `{username,password,email}` → `{token,user}` 假设
- [ ] **`GET /api/orders/:orderId` 的完整 body**（TBD）——前端 OrderDetail 页现在是可选链防御式渲染，定了补全
- [ ] **4 态模型下"已送达待签收"没有独立状态**：confirm-receipt 直接把状态翻成 DELIVERED，意味着用户 IN_TRANSIT 时就能点签收。产品逻辑对不对？
- [ ] **取消订单端点缺失**——线框图有 Cancel 按钮，契约没有端点。要么后端加 `POST /api/orders/:id/cancel`，要么砍功能
- [ ] **`GET /api/stations` 响应**（TBD）——下单第 1 步地图展示要用
- [ ] **支付失败 vs 订单失败的错误形状**（TBD）——前端要在支付页区分文案
- [ ] **`POST /api/ai/parse`**（P1 前端提议，未入契约）——后端谁认领？可先正则桩
- [ ] **`POST /api/auth/logout`** 是服务端失效还是纯客户端（TBD）——前端现在"尽力调用、本地必清"
- [ ] 枚举复核：`ROBOT|DRONE`；`PENDING|IN_TRANSIT|DELIVERED|CANCELLED`；`STANDARD|EXPRESS`
